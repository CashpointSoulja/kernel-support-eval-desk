# Documentation

Read these files in order:

1. [`ELI5.md`](ELI5.md): Explains the company, the support problem, the workflow, safe refusal, and regression checks in everyday language.
2. [`PRD.md`](PRD.md): Defines the audience, problem, outcome, requirements, guardrails, scope, and acceptance checks.
3. [`FIVE_WHYS.md`](FIVE_WHYS.md): Traces why useful support outcomes fail to become durable checks.
4. [`JTBD.md`](JTBD.md): States the jobs and visible success conditions for support, data-quality, and quality owners.
5. [`DECISIONS.md`](DECISIONS.md): Records five product and implementation choices with their costs.
6. [`METRICS.md`](METRICS.md): Separates checks the concept can report from outcomes that need a controlled pilot.
7. [`TEST_PLAN.md`](TEST_PLAN.md): Lists automated, workflow, usability, access, and boundary checks.
8. [`TEST_RESULTS.md`](TEST_RESULTS.md): Records the latest command results and distinguishes implementation checks from deliberate demo failures.
9. [`VIABILITY.md`](VIABILITY.md): Describes the product wedge, what is demonstrated, what is unproven, and a validation path.
10. [`V2_ROADMAP.md`](V2_ROADMAP.md): Orders possible improvements from evidence inspection through pilot readiness.
